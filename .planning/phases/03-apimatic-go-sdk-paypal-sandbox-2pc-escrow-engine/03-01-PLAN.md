# Plan 03-01: APIMatic Go SDK Generation & Verification (`TASK-05`)

## Objective
Implement and verify the strongly-typed APIMatic-generated Go SDK (`sdk/paypal-go-apimatic`) for PayPal Sandbox (`Orders v2`, `Payments v2`, `Tracking v1`, `Disputes v1`) with thread-safe OAuth2 token caching, `PayPal-Request-Id` idempotency header injection, transient retry backoff, and deterministic Sandbox replay fallback.

## Tasks
1. **Upgrade `sdk/paypal-go-apimatic/client.go` (`< 250` lines)**:
   - Implement `Client` with `GetAccessToken(ctx)`, `InvalidateToken()`, `doJSON(ctx, method, path, paypalRequestID, reqBody, respOut)`, exponential retry on `502`/`503`/`504`, `PayPal-Request-Id` header enforcement, and `FallbackMode` (`TALOS_SANDBOX_FALLBACK_ENABLED=true`).
2. **Upgrade `sdk/paypal-go-apimatic/orders_v2.go`, `payments_v2.go`, `tracking_v1.go`, `disputes_v1.go` (`< 250` lines each)**:
   - Implement `CreateOrder`, `AuthorizeOrder`, `CreateAndAuthorizeOrder`, `CaptureAuthorization`, `VoidAuthorization`, `CreateTrackingBatch`, and `ProvideDisputeEvidence`.
3. **Add `sdk/paypal-go-apimatic/apimatic-context-manifest.json` and `sdk/paypal-go-apimatic/client_test.go` (`< 250` lines)**:
   - Test OAuth2 token acquisition & caching (verifying single `/v1/oauth2/token` roundtrip across multiple requests), `PayPal-Request-Id` injection, all endpoints (`Orders v2`, `Payments v2`, `Tracking v1`, `Disputes v1`), transient `503` retry recovery, validation error handling, deterministic replay fallback, and optional live `.env` OAuth2 smoke verification.
4. **Verify**:
   - Run `go test -race -v ./...` in `sdk/paypal-go-apimatic`.
