# Phase 2 Plan 01 (`TASK-03`): Rust Zero-Trust KYA Mandate Signer/Verifier (`Ed25519` + RFC 9421 + RFC 8785) & PayPal Webhook CRC32 Verifier

## Objective
Replace stub string signatures in `services/firewall-rs/src/mandate.rs` and `services/firewall-rs/src/webhook_verify.rs` with real `ed25519-dalek` signing and constant-time verification (`verify_strict`), RFC 8785 JCS canonicalization, RFC 9421 HTTP Message Signature verification, and IEEE 802.3 CRC32 PayPal Webhook verification.

## Tasks
1. **Upgrade `services/firewall-rs/src/mandate.rs` (< 250 lines)**:
   - Implement deterministic/seeded and ephemeral `Ed25519` keypair generation and hex decoding using `ed25519_dalek::{SigningKey, VerifyingKey, Signature, Signer}` and `sha2::Sha256`.
   - Implement RFC 8785 JCS canonicalization (`canonicalize_mandate`) and `sign_mandate` returning a real 64-byte `Ed25519` signature and in-memory registry storage so `/v1/mandates/verify` works with either an embedded `mandate` object or `mandate_id` lookup.
   - Implement `verify_mandate` using `VerifyingKey::verify_strict` plus hard checks for `expires_at_unix`, `allowed_categories` (case-insensitive), `max_channel3_spread_bps` / `max_spread_bps` (≤ 500 bps), `max_amount_cents` (returning `AMOUNT_EXCEEDS_MANDATE_CAP_STEP_UP_REQUIRED` and `requires_step_up: true`), and optional RFC 9421 HTTP Message Signature headers (`Signature-Input` and `Signature`).
   - Add unit tests proving valid mandate verification, tampered `max_amount_cents` rejection (`MANDATE_SIGNATURE_INVALID`), expired mandate rejection (`MANDATE_EXPIRED`), unauthorized category rejection (`CATEGORY_NOT_ALLOWED`), spread cap rejection, RFC 9421 header verification, and `< 1000 us` latency.
2. **Upgrade `services/firewall-rs/src/webhook_verify.rs` (< 250 lines)**:
   - Compute IEEE 802.3 CRC32 checksum via `crc32fast::hash(req.raw_body.as_bytes())`.
   - Construct `<transmission_id>|<transmission_time>|<webhook_id>|<crc32_decimal>` validation string.
   - Validate `cert_url` (`https://*.paypal.com/...`) and verify cryptographic signature (`Ed25519`/SHA-256 or deterministic sandbox signature) in `< 1000 us`.
   - Add unit tests for valid webhook verification, tampered body CRC32 mismatch, untrusted `cert_url` domain rejection, and invalid signature rejection.

## Verification Criteria
- `cargo fmt --all -- --check` exits 0
- `cargo clippy --all-targets --all-features -- -D warnings` exits 0
- `cargo test` in `services/firewall-rs` passes all `mandate` and `webhook_verify` unit tests
- Both `mandate.rs` and `webhook_verify.rs` are `< 250` lines
